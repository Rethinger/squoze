# Requirements — контракты дистилляции (determinism, format safety, cache stability)

Status: implemented (TSK-001..009), docs in progress · Created 2026-09-04 · Feature Spec

## Контекст / проблема

Аудит бенчмарков в 2papi (`docs/benchmark-audit.md`) прогнал squoze v0.2.0 через
корпус из 15 кейсов и реальные файлы репозитория и нашёл **пять нарушений
собственных контрактов** движка; ещё три ((f), (g), (h)) всплыли уже в ходе
работы над спекой. Сжатие при этом работает лучше заявленного
(87–99% на машинном выводе, медиана 96.14%), то есть проблема не в силе сжатия,
а в его предсказуемости и безопасности.

Заявленные контракты (`README`, доккоменты пакетов):

| Контракт | Где заявлен | Статус в v0.2.0 |
|---|---|---|
| cache-safe: одинаковые байты → одинаковый выход | `README`, `compress` | **нарушен** |
| «Prose, code and JSON blobs are routed but NOT mutated» | `internal/router/router.go:1` | **нарушен** |
| never-elide: строки с признаком ошибки выживают | `internal/compress/compress.go:5` | **нарушен при >50 ошибок** |
| idempotency: `Apply(Apply(x)) == Apply(x)` | `internal/compress/compress.go:6` | соблюдён |
| fail-open | `internal/distill/json_tabular.go:22` | соблюдён |

Все четыре нарушенных контракта восстановлены и закрыты тестами в пакетах
`internal/router`, `internal/engine`, `internal/compress`, `internal/distill`;
подтверждение — в `tasks.md` (TSK-009, таблица приёмки NFR).

Измеренные нарушения:

- **(a)** Исходник, густой на тест-маркеры, элидируется как машинный вывод
  (29159 → 4245 Б, синтаксически битый Go). `KindCode` объявлен в
  `router.Kind`, но `Classify` **никогда его не возвращает** — детектора кода
  просто нет. Частота на обычном коде близка к нулю (1 из 93 файлов ≥4 КБ, и
  это генератор фикстур), но механизм реален.
- **(b)** JSON превращается в Markdown-таблицу, поля конверта (`has_more`,
  `object`, имя обёртки) теряются. Модель не может понять, что есть ещё страницы.
  Порог смены типа — всего 10% экономии (`len(tbl) < len(s)*9/10`).
- **(c)** Порядок колонок таблицы случаен: до 4 разных вариантов на 12 свежих
  движках. Причина — `for k := range m` по Go map в `tryTabularLifting`.
  Промпт-кэш провайдера не может попасть никогда.
- **(d)** Кросс-турный dedup переотправляет ранний ход целиком: 4245 → 29159 Б
  (+24914). Причина — `targets[i].content` мутируется дедупом, а затем
  сравнивается сам с собой в гарде `out != t.content`
  (`internal/engine/stream_scanner.go:124`).
- **(e)** При `MaxKept=50` и 200 падениях recall по строкам ошибок = 8%, и
  маркер об этом не сообщает: модель не знает, что часть падений выброшена.
- **(f)** Настоящий машинный вывод уходил в `KindProse` и не сжимался вовсе:
  трасса `panic:` с горутинами, вывод `go build` из строк `file.go:12:5: ...`
  — ни одна из них не даёт трёх попаданий в старую таблицу маркеров. Найдено
  при написании детектора кода (FR-4): без `crashHits` и распознавания
  диагностик AC-4.2 нельзя было сформулировать так, чтобы обе стороны
  (код против вывода) держались одновременно.
- **(g)** `sanitizeCell` режет ячейку на 80 символах молча: модель видит
  обрезанный `error_message` и не может понять, что текст продолжался, а
  «экономия» в отчёте частично оказывается удалением данных, а не сжатием.
- **(h)** Направление кросс-турного dedup было выбрано наоборот: v0.2.0
  оставляет **последнюю** копию целой и переписывает более ранние. Ранняя копия
  — это ровно те байты, что уже лежат в префиксе промпт-кэша провайдера, так
  что любая её правка обнуляет кэш с этой позиции. Плюс маркер называл номер
  последнего хода, поэтому переписанная история не «устаканивалась» никогда:
  с каждым новым ходом текст маркера снова менялся.
- **(i)** `KindJSON` недостижим для тел больше `probeLen` (8 КБ), и попытка его
  получить не бесплатна. `Classify` валидирует **усечённый** префикс, а
  усечённый JSON невалиден по определению, поэтому любой JSON-результат
  инструмента крупнее 8 КБ — то есть любой, который стоит сжимать — уходит в
  `KindProse`. Наблюдаемого расхождения нет: оба места вызова в
  `internal/engine` обращаются с `KindJSON` ровно как с `KindProse`
  (`squeezeText` отказывается от обоих, `distillText` проваливается мимо
  своего `switch` в Pass 4), а сам JSON к этому моменту уже был предложен
  `DistillJSON` в Pass 2. Цена — полный разбор 8 КБ впустую плюс выброшенный
  `json.SyntaxError`: единственная аллокация во всём роутере (24 Б, 1 alloc/op
  на кейсе `Classify/json_over_probe`). Найдено при написании
  `internal/router/bench_test.go`: пин ветки в бенчмарке отказался считать
  фикстуру на 270 КБ JSON-кейсом.

## Функциональные требования

- **FR-1 (Must)** — WHEN один и тот же вход подаётся в несколько свежих движков,
  the system SHALL возвращать байт-идентичный выход.
  - **AC-1.1** — Given JSON-массив из ≥3 однородных объектов, When он поднимается
    в таблицу на 12 свежих движках, Then заголовок таблицы совпадает во всех 12.
  - **AC-1.2** — Given любой кейс корпуса, When обработан дважды свежими
    движками, Then выходные байты равны.

- **FR-2 (Must)** — Смена типа данных (JSON → таблица) SHALL происходить только
  при существенной экономии, и SHALL сохранять поля конверта.
  - **AC-2.1** — Given `{"object":"list","data":[...],"has_more":true}`, When
    массив поднят в таблицу, Then `has_more` и `object` присутствуют в выходе.
  - **AC-2.2** — Given подъём в таблицу экономит меньше порога, When вызван
    `DistillJSON`, Then выход остаётся валидным JSON (fallback на pruning).
  - **AC-2.3** — Given выход остался JSON, When он распарсен, Then парсинг успешен.

- **FR-3 (Must)** — WHEN более поздний ход перечитывает уже виденный файл, the
  system SHALL NOT менять байты более раннего хода — ни в сторону роста, ни в
  сторону сжатия: они уже отправлены провайдеру и лежат в префиксе кэша.
  - **AC-3.1** — Given 4-турная сессия, где ход 3 перечитывает файл хода 1, When
    ходы обработаны последовательно, Then содержимое message 1 после хода 3
    **байт-в-байт** равно содержимому после хода 2.
  - **AC-3.2** — Given dedup сработал, When ранний ход заменён маркером, Then
    замена действительно попадает в тело (а не откатывается гардом).
  - **AC-3.3** — Given повтор найден, When он свёрнут, Then свёрнута **поздняя**
    копия, а маркер ссылается на номер **первого** хода — то есть на величину,
    которая с ростом сессии больше не меняется.

- **FR-4 (Must)** — The system SHALL классифицировать исходный код как
  `KindCode` и не мутировать его.
  - **AC-4.1** — Given файл с `package`/`import`/`func` на началах строк, When
    вызван `Classify`, Then результат `KindCode`.
  - **AC-4.2** — Given реальный вывод `go test` с трассой паники (содержит
    строки кода), When вызван `Classify`, Then результат `KindTestOutput` —
    детектор кода не должен глушить настоящий машинный вывод.
  - **AC-4.3** — Given любой файл `.go`/`.mjs` ≥4 КБ из репозитория, When
    прогнан через движок, Then байты не изменились.

- **FR-5 (Should)** — WHEN лимит `MaxKept` отбрасывает строки с признаком
  ошибки, the system SHALL сообщить их количество в маркере.
  - **AC-5.1** — Given 200 падений и `MaxKept=50`, When блоб сжат, Then маркер
    содержит число отброшенных строк ошибок.

- **FR-6 (Must)** — The system SHALL распознавать как машинный вывод те его
  формы, которые не содержат слов `FAIL`/`PASS`: трассы паник и вывод
  компилятора.
  - **AC-6.1** — Given вывод с `panic:` и `goroutine N [running]:`, When вызван
    `Classify`, Then результат `KindTestOutput`.
  - **AC-6.2** — Given вывод сборки из строк вида `path/file.go:12:5: message`,
    When вызван `Classify`, Then результат `KindTestOutput`.
  - **AC-6.3** — Given строка с временной меткой в начале, When она похожа на
    диагностику, Then она не считается диагностикой (это лог, не компилятор).

- **FR-7 (Must)** — WHEN подъём в таблицу обрезает содержимое ячеек, the system
  SHALL сообщить количество обрезанных ячеек в заголовке таблицы.
  - **AC-7.1** — Given 20 строк с полем длиннее лимита ячейки, When массив
    поднят в таблицу, Then заголовок содержит `20 cells truncated`.
  - **AC-7.2** — Given все ячейки укладываются в лимит, When массив поднят в
    таблицу, Then заголовок про обрезку молчит.
  - **AC-7.3** — Given значение постоянной колонки не укладывается в лимит,
    When колонки выносятся в заголовок, Then эта колонка **не** выносится
    (обрезанное значение в заголовке некому раскрыть) и остаётся колонкой.

- **FR-8 (Should)** — WHEN усечённый префикс не может быть валидным JSON, the
  system SHALL NOT запускать `json.Valid` — находка (i).
  - **AC-8.1** — Given тело, чей обрезанный префикс не закрывается парной
    скобкой, When вызван `Classify`, Then разбора JSON не происходит и
    аллокаций у роутера остаётся ноль.
  - **AC-8.2** — Given любое тело, которое до изменения давало `KindJSON`,
    When вызван `Classify`, Then результат тот же. Эквивалентность
    доказывается, а не проверяется выборочно: валидный JSON после
    `TrimSpace` всегда заканчивается скобкой, парной своей первой, поэтому
    новая проверка способна отсечь только те вызовы, которые вернули бы
    `false`.
  - **AC-8.3** — Given корпус кейсов роутера, When прогнан `Classify`, Then
    вердикты совпадают с зафиксированными до изменения.

## Нефункциональные требования

- **NFR-1 (латентность)** — p95 движка на кейс корпуса SHALL NOT вырасти более
  чем на 15% против базовой линии v0.2.0 (worst-case p95 = 6.98 мс, медиана
  p50 ≤ 4 мс). Детектор кода ищет опенер по префиксу (≤8 КБ); плотность
  маркеров считается по выборке окон, а не по всему блобу.
  - Роутер измеряется напрямую (`internal/router/bench_test.go`), потому что
    `Classify` вызывается на каждом блоке инструмента **до** любого сжатия —
    его цену платят и те блобы, которых никто не трогает. Ограничение выборки
    (`maxWindows*windowLen` = 96 КБ) SHALL быть видно в замере: 270 КБ и
    2700 КБ обязаны стоить одинаково.
- **NFR-2 (идемпотентность)** — `Apply(Apply(x)) == Apply(x)` SHALL сохраняться
  для всех 15 кейсов корпуса.
- **NFR-3 (fail-open)** — при любой ошибке парсинга/паники транспорт SHALL
  вернуть исходные байты; сжатие никогда не роняет запрос.
- **NFR-4 (качество)** — доля сэкономленных байтов на машинном выводе SHALL NOT
  упасть ниже 85% медианы по корпусу (базовая линия — 96.14%).
  Знаменатель — только сжатые кейсы (`Touched`), как считает сам харнесс
  (`2papi/test/squozebench/main.go:298`). Кейс класса `must-not-touch`,
  который перестал сжиматься, из знаменателя **уходит** — это не потеря
  экономии, а исполнение контракта; сравнивать версии нужно на общем
  подмножестве.

## Ограничения

- Поведение по умолчанию остаётся обратно совместимым для встраивания в 2papi:
  публичный API `squoze.NewEngine` / `Apply` не меняется.
- Пороги (`MinBytes`, `MaxKept`) остаются настраиваемыми через `compress.Params`.
- Изменения не должны требовать нового поля конфигурации в 2papi.

## Вне рамок

- Замер Δaccuracy на живом провайдере — отдельный слой (провайдер
  `gpt.crax.lol` доступен, 44/47 моделей рабочие; usage-цифры провайдера
  недостоверны — `prompt_tokens=1016` на любой запрос, поэтому токены считаем
  локально `gpt-tokenizer`).
- Улучшения 2papi (сравнение с bifrost) — согласуются с пользователем отдельно.
