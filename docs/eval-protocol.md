# squoze eval protocol

Двухуровневая стратегия оценки качества. Уровень 1 бежит на каждый коммит,
уровень 2 — перед релизом (нужны API-ключи, прогон подтверждает владелец).

## Уровень 1 — детерминированные фикстуры (каждый коммит)

`go test ./internal/eval -v` — таблица «было → стало» по классам:

| Фикстура | Класс | Контракт |
|---|---|---|
| go_test_600 | вывод go test с FAIL | FAIL-строки целы, savings ≥ 80% |
| pytest_verbose | pytest с FAILED/E-строками | факты ошибок целы, ≥ 30% |
| server_logs_errors | таймстампed логи с ERROR | ERROR целы, ≥ 70% |

Провал любого контракта = красный тест. Это защищает от регрессий качества
при изменении роутера/компрессора.

## Уровень 2 — датасетные прогоны (перед релизом v0.1+)

Цель: доказать, что сжатие НЕ портит ответы модели, и измерить экономику.

### Датасеты

1. **LoCoMo** (long multi-session conversations) — QA accuracy на сжатой
   истории vs полной. Метрика: Δaccuracy ≤ 2 п.п. от базлайна.
2. **RULER** (needle-in-haystack variants) — retrieval/мulti-hop трассировка
   через сжатый контекст. Метрика: n-trace / n-vt ≥ 0.95 базлайна.
3. **BFCL v3** (function calling) — агента циклы с tool output через squoze.
   Метрика: match rate без деградации.

### Протокол прогона

1. Провайдер: Anthropic (`claude-sonnet`) + OpenAI (`gpt` семейство), ключи
   в env, не в репо.
2. Базлайн: тело БЕЗ squoze → ответы → скор.
3. Эксперимент: то же через `squoze proxy --upstream ...` → ответы → скор.
4. Сравнение: Δaccuracy, savings% (из X-Squoze заголовков), latency p50/p95
   (overhead прокси).
5. Критерий PASS: Δaccuracy ≤ 2 п.п. И savings ≥ 50% И overhead < 15ms p95.
